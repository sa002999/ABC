日期：2026-10-21。狀態：完成。第 6 步付款與正式預約成立尚未開始。

## 已完成

| 項目 | 結果 |
|---|---|
| 資料庫 | 新增不可回寫舊 migration 的 `0002_quotes_holds`，建立 booking_drafts、pricing_quotes、resource_holds、hold_items；原 12 張目錄／排程表與 7 份 JSON 保留，共 16 張應用資料表 |
| 正式報價 | 後端從目前 DB 計算含稅 JPY；情侶套餐一次、第三人加價、腰帶、攝影包含／加購不重複；回傳明細、總價與不可變報價識別 |
| 報價有效期 | 最長 10 分鐘，且不超過場次開始；草稿／報價不占庫存。草稿、價格、商品狀態改變或到期須重新報價 |
| 會員隔離 | 驗證 Firebase RS256 ID token 與已驗證信箱；UID 取自已驗簽 sub，草稿／報價／保留僅本人可存取；正式服務沒有跳過驗證的測試開關 |
| 全員保留 | 同店同日交易鎖，檢查全部和服、腰帶與場次名額後一次提交；任何不足整筆失敗，不會部分保留 |
| 同款多件 | 同款有 3 件即能提供 3 件；同日不同場次仍共同扣庫存，當日不重複出租；場次另依實際旅客人數扣名額 |
| 安全重送 | 相同保留鍵回原結果，不重扣或續期；同鍵不同內容拒絕，同一報價不能換鍵多占；重整恢復伺服器原草稿／報價與到期時間 |
| 取消與到期 | 本人可取消未付款保留返回摘要；最長 10 分鐘到期即不再占用，背景每 30 秒標成 EXPIRED；待確認付款／已成立資源不因期限自動釋放 |
| React | 沿用報價單一按鈕與原尺寸／樣式；連接草稿、報價、保留、恢復與取消；發生資源／價格衝突時要求重報價 |
| 付款界線 | booking/payment capability 仍為 false；保留後顯示付款未開放，不掛載 TapPay 欄位、不載 SDK、不收卡號、不成立預約 |
| 啟動文件 | SOP 已補上 hold-expiry 啟動、更新 migration、驗證及排錯；沒有停止 React、清空 volume、重建 JSON 或操作 AWS／thread-app |

## 驗證

- `npm run build`：TypeScript／Vite 通過，產出 CSS 與第 4 步相同（`index-Cf0nJG-r.css`）。
- `npm test`：36 項通過，包含分開開啟草稿／報價／保留能力而維持付款停用、冪等鍵與憑證傳遞、409 衝突處理。
- `tests/verify_booking.py`：61 項在獨立 PostgreSQL 測試庫通過，包含報價不占資源、情侶與第三人／攝影計價、完整回滾、每日庫存、同款多件、腰帶不足、到期邊界、本人隔離、假造 JWT 拒絕、取消／重送及不延長期限。
- 真正多連線競爭：8 筆同時搶同日不同場次的 3 件同款，恰好 3 筆成功；6 筆搶 2 個場次名額，恰好 2 筆成功；6 次相同冪等請求只建立 1 筆保留。
- `tests/verify_api.py`：52 項既有 API 查詢回歸通過，包含 GET 強制唯讀、城市／商品／日圓價格、休業日、日本時間與 CORS。
- Firebase 驗簽程式測試使用本機 RSA 測試金鑰；實際容器可取得 Google 公開驗簽金鑰（4 把），沒有輸出會員 token 或私鑰。
- 瀏覽器實際填選兩位旅客與商品，經七步抵達摘要。政策未勾選時按鈕停用，沒有代替使用者同意條款、提交會員正式報價、建立開發庫保留或付款；完整已驗證身分報價／保留成功與錯誤流程由隔離 API 測試覆蓋，真實會員瀏覽器流程仍可由使用者自行驗收。
- 摘要頁檢查 360／390／640／767／768／1024／1032／1376／1440px，共 9 組均無水平溢出：[檢查紀錄](qa/step5-responsive.json)。暫時視窗覆寫已重設。
